# Правила учёта

Нарушение любого пункта — ошибка учёта, а не вопрос стиля.

- **Одна операция — одна транзакция.** Документ, остаток и строка журнала
  меняются внутри одного `UnitOfWork`. Никаких записей вне него.
- **Остаток меняется только вместе с журналом.** Каждое изменение `stock`
  сопровождается `uow.journal.record(Movement.…)`. Сверка
  (`GET /api/reconciliation`) обязана оставаться зелёной.
- **Остаток читается под блокировкой.** Перед изменением —
  `uow.stock.get_for_update(...)`, документ — `get_for_update(id)`.
- **Подтверждения идемпотентны.** Метод перехода документа возвращает
  `bool`; обработчик меняет остатки только при `True`.
- **Создающие операции принимают ключ идемпотентности** и идут через `_once`.
- **Правила — в домене.** Проверки «хватает ли», «можно ли перейти в статус»,
  «действует ли ФФ» живут в `app/domain`, не в SQL и не в роутере.
- **ФФ не удаляется физически.** Только `deleted_at`. Остатки и история
  ссылаются на строку склада.
- **Слои:** `api → infrastructure → application → domain`. Домен и
  приложение не импортируют SQLAlchemy, FastAPI, Pydantic.
